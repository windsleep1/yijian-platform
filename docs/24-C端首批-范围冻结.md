## 4. `packages/api-core` 怎么复用

**只装"必须一致的那三件事"**（纯 TS、零依赖、无 React）：

```
RETRYABLE_AUTH_CODES / FATAL_AUTH_CODES                       ← 码集
classifyAuthFailure(code) -> "retryable" | "fatal" | "other"   ← 穷尽 switch
createSingleFlightRefresh({ storage, apiBase, fetchImpl })      ← 单飞 + Rotation 存回
```

| 项 | 做法 |
|---|---|
| 消费方式 | `apps/web/tsconfig.json` 的 **`paths`** → `../../packages/api-core/src/index.ts`（**不产出 dist**：源码即唯一真相） |
| 存储 | **依赖注入**：包只要求 `{ getRefreshToken, setTokens }` 形状，**它不知道 localStorage 是谁** ⇒ 将来迁 httpOnly cookie 时**包不用改** |
| **不进包** | 信封解包、`trace_id`、雪花 ID 体检、`send()` 里对 `classifyAuthFailure` 的三分支处理 |
| 门禁 | `apps/web` 加 `format:check:shared`（覆盖 `packages/`）——与 admin 同款 |
| 反向检查 | `tools/local-verify/check-auth-chain.mjs` 已扫 `apps/<app>/src`；**`apps/web` 一出生就在扫描范围内**，不需要改脚本 |

**四级保证**（从强到弱）：① 结构性唯一（**唯一的真保证**）② 编译期穷尽（`tsc --noEmit`）③ 包内单测钉全量码表 + 变异 ④ CI 反向检查。

★ **本轮新增的一条**：`apps/web` 的 `lib/api.ts` **从第一天就用包** —— admin 当初是"先复制、后抽"，那次留了一段真实的一致性风险窗口（§9.2）。C 端不必重演。

## 6. 逐条说明

### ① BL-14：为什么"只做 DDL 那一半"（附实测）

你说的"首批做"与 `docs/22` §5.3 的"首批不做每日一练"**不矛盾**：那个 BL 本来就是两件事。

`docs/21` §4.4 写过一句：*"这也是它必须在做 daily 那个批次里做、而不是当成一句 DDL 顺手加的原因"* ——
理由是"**约束从未存在过 ⇒ 库里很可能已有重复** ⇒ 建索引会直接失败"。

**本次实测把这个前提推翻了**：

```
全仓 practice_sessions.mode 的写入取值：只有 'chapter'
  tools/local-verify/seed-stats.py:286      VALUES ($1,$2,'chapter',…)
  apps/api/tests/test_stats_service.py:179  VALUES (:id,:uid,'chapter',…)
  （seed-stats.py:320 那个 'mock' 写的是 exams 表，不是 practice_sessions）
app/ 里也没有任何 practice 接口 —— api/router.py:42 的 practice.router 是**注释掉的**
```

⇒ **`mode='daily'` 的行数恒为 0** ⇒ **今天加这个部分唯一索引是零风险**，而且**从此不会再有脏数据**。
等"做 daily 那批"再加，反而要**先写一遍查重 + 合并策略**。

**修正版表达式**（§4.4 实测可建、且真拦重复）：

```sql
CREATE UNIQUE INDEX uq_practice_daily
  ON practice_sessions (user_id, ((created_at AT TIME ZONE 'Asia/Shanghai')::date))
  WHERE mode = 'daily';
```

⚠️ 两点别写错：**不能**用裸 `date(created_at)`（`date(timestamptz)` 是 STABLE 不是 IMMUTABLE，PG 拒绝）；
**没有** `is_deleted` 列（`practice_sessions` 上不存在）。
**两处都要加**：`db/schema.sql`（新库）+ `db/migrations/*.sql`（已有库）——这是本仓的结构变更规矩。

### 9.3 ★ 两处修正（一条是**产品缺陷**，一条是**机制事实**）

#### 修正 ①（产品缺陷）：白名单必须含 `viewer`

§6.5.2 写的是 `super_admin / admin / researcher / teacher / operator`。但 **`viewer` 是管理端只读岗** ——
`test_viewer_can_read_all_five_endpoints` 等用例证明它要读 `/admin/users`、`/admin/audit-logs`、
`/admin/questions`、`/admin/stats`、`/admin/exams`；`ASSIGNABLE_ROLES` 里也有它。

⇒ 不改的话 **`viewer` 角色整个作废**：拿不到 `pc` 会话，`h5` 会话又被会话墙挡——它**一个接口都读不了**。
⇒ **`ADMIN_PLATFORM_ROLES` 加 `viewer`。**

**可证伪判据**：修好 A 层之后，`test_viewer_can_read_all_five_endpoints` **仍然必须是绿的**；
如果它红了，就是白名单的问题，**不是测试的问题**。

#### 修正 ②（机制事实）：router 级依赖**天然在最前** —— §6.5.3 的"权限墙在前"做不到

实测装着的 FastAPI **0.115.14** 源码（不是推测）：

```
APIRouter.include_router :  current_dependencies.extend(dependencies)   # router 级先加
                            current_dependencies.extend(route.dependencies)
APIRoute.__init__        :  for depends in self.dependencies[::-1]: insert(0, …)   # 保持列表顺序
```

⇒ 挂成 **router 级依赖 = 一定在其他依赖之前**。
**后果**：**"完全没权限的账号"从 `40301` 变成 `40306`**（B 层那 4 处）——
这不是安全回归（两者都是**拒绝**），是**返回值**变了；而 §6.5.5 里
"既有 3 条用例**预期不用改** ✅"的**前提因此不成立**。

三个选项：

| 选项 | 评价 |
|---|---|
| ① 接受 `40306`，改那 4 处断言 | 简单，但**把"权限墙"这道守卫拆了** —— 它们存在的意义就是钉住 `40301` |
| ② **保住 `40301` 的覆盖**：改用"**能持管理端会话、但缺该权限**"的账号（如 `teacher`）来断言 | ✅ **建议**。守卫**不变弱**，只是换了个"有身份、缺能力"的账号 —— 这正是 §6.5 判据（**身份 ≠ 能力**）的正面用法 |
| ③ 逐个路由挂依赖以换顺序 | ❌ **否决**：丢掉"一处挂"，而**漏一个的症状是静默的**（那个接口不需要管理端会话也能读） |

对 `test_student_has_no_stats_permission`：**改名**为 `test_student_cannot_hold_admin_session`（断言 `40306`），
让名字和断言一致 —— **测试名是契约的文档**（名字说 `has_no_stats_permission` 而断言是会话墙码，下一个人会被误导）。
⚠️ 我**原本在同一段建议"再补一条 `teacher` 缺 `stats:read` ⇒ `40301`"—— 这个建议是错的**：
`teacher` 的权限集含 `stats` 模块 ⇒ **它有 `stats:read`**。
逐条核过种子的角色→权限表之后确认：**`stats:read` 这一格保不住**（六个可持 `pc` 会话的角色**全都有**它）。
详见 §9.2.2。

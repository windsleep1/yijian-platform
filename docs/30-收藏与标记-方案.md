## 2. 两个决策点（**要你拍板**）

### ★★ D1. 「标记」存在哪 —— 本批最关键的决策

你的原话是"标记：`practice_items.marked` 已有字段"。**这个字段的粒度是错的**：

```
practice_items (id, session_id, user_id, question_id, ..., marked)
                          ^^^^^^^^^^ 会话内！
```

后果（**都不报错，只是行为怪**）：
- 在练习 A 里标记第 3 题 ⇒ 打开练习 B 的**同一道题**，答题卡显示**未标记**（那是另一个 item）；
- 而"错题本筛已标记"是**跨练习**的问法（错题本按 `question_id` 聚合）⇒ 只能写成
  `EXISTS(… practice_items WHERE marked)`，即"**曾经**标过"；
- 于是 **错题本说"已标记"、答题卡说"未标记"** —— **同一个事实两种说法**（本项目红线）。

| 方案 | 存储 | 粒度 | 迁移 | 副作用 | 判定 |
|---|---|---|---|---|---|
| **A**（你的原计划） | `practice_items.marked` | 会话×题 | **0** | 无 | ⚠️ 能过你的三条验收，但留下"两处说法不一致" |
| **B** | `user_question_state` **加一列** `marked` | 用户×题 | 1 列 | ★★ **会改抽题顺序**（见下） | ❌ 不推荐 |
| **C**（**推荐**） | **新表 `question_marks`** | 用户×题 | 1 表 | 无 | ✅ 语义单一、零副作用 |

**B 的副作用为什么是致命的**：`user_question_state` 有行**本身就参与抽题**——
`_PICK_SQL` 里 `ORDER BY (uqs.id IS NOT NULL), q.id`（"未做过的优先"）。
为了标记一道**还没答过**的题就得插一行 ⇒ 它立刻被当成"做过的" ⇒ **抽题顺序变了**，
而这是**不报错的**行为改变（E2E `p2b1` 依赖"未做过的优先"的确定性）。

**C 的做法**（推荐）：

```sql
-- db/migrations/20261004-01-question-marks.sql
CREATE TABLE question_marks (
  id          BIGINT PRIMARY KEY,
  user_id     BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  question_id BIGINT NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
  subject_id  BIGINT NOT NULL,            -- 给"按科目筛选"用，避免每次 join
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uq_question_marks ON question_marks(user_id, question_id);
CREATE INDEX idx_question_marks_user ON question_marks(user_id, created_at DESC);
```

★ **选了 C，就必须同时"作废"另一处写法**（硬约定：一个字段只能有一种写法）：
把 `practice_items.marked` / `exam_attempt_items.marked` **保留但标注为不采用**
（在 `db/schema.sql` 的列注释 + `session/[id]/page.tsx` 的注释 + `docs/21` BL-21 三处各写一句
"**标记的用户态一律走 `question_marks`；这两列是卷面内标记，未接线、不要用**"）。
⚠️ **不删列**：删列是破坏性迁移，而它们没碍事 —— 但**必须写明谁是唯一真相**。

## 3. 接口设计（**新增 5 个**）

### 3.1 写：4 个（两个概念各自**对称**，都**幂等**）

| 方法 | 路径 | 语义 | 幂等判据（硬约定 C） |
|---|---|---|---|
| `PUT` | `/practice/favorites/{qid}` | 收藏 | 已有行 ⇒ **零写入**，返回 `{favorited: true}` |
| `DELETE` | `/practice/favorites/{qid}` | 取消收藏 | 没有行 ⇒ **零写入**，返回 `{favorited: false}` |
| `PUT` | `/practice/marks/{qid}` | 标记 | 同上（`{marked: true}`） |
| `DELETE` | `/practice/marks/{qid}` | 取消标记 | 同上（`{marked: false}`） |

**准入**（4 个都一样）：只允许对 `status='published'` 且 `is_deleted=false` 的题操作，
否则 **`40401`**（不是 403）—— 否则会留下指向"用户看不到的题"的脏标记，
而那种脏标记在列表里**表现为一个空题干**（比报错更难查）。

### 3.2 读：1 个

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/practice/favorites?kind=favorite\|marked&subject_id=&page=&page_size=` | 两个列表**同形状**（题目 + 分面 + 分页），`kind` 只切题源；默认 `favorite` |

★ **为什么读接口要带 `kind`**（这是本批一个**必须补的洞**）：
标记可以打在**任何**题上（包括你**从没答错**的题），那种题**不在错题本里** ⇒
如果只有"错题本筛已标记"，用户会问"**我标的题去哪看？**"。
⇒ 两个列表共用一个页面（页签：收藏 / 标记）、一条读接口。
（若你决定"本批只管错题本里的标记"，那就把这一点**记成 BL**，见 §7 的选项 B。）

### 3.3 既有接口扩展 2 处

| 接口 | 扩展 | 为什么 |
|---|---|---|
| `GET /practice/sessions/{id}` | 每个 item 补 `marked` + `favorited` | 答题页两个按钮要显示**当前态**；★ 必须**一次查询**搞定（两个 `EXISTS` 或在 `_SELECT_ITEMS` 里 join），**不许 N+1** |
| `GET /practice/wrong-questions` | 加 `marked_only: bool = false` | 你的验收：错题本筛"已标记" ★ 分面**恒为全量**（照 P2c-2 那次修正：分面随筛选收缩会导致**切不回去**） |

**合计：新增 5 个接口 + 2 处扩展。**（路由数 67 → 72；`api/v1` 模块 13 → 13，不新开文件）

### 9.3 ★ 本批的两个"过程坑"（都不是代码逻辑错，但都会让人误判成别的东西）

1. ★★ **跑过"定向子集"之后，全量跑不起来（死锁）**：子集的覆盖率门禁必然失败 ⇒
   回执记 `rc=2` ⇒ preflight 读到"上一轮失败"就 ❌ ⇒ **管道拒绝继续** ——
   而**全量正是那个能覆盖回执的操作**。绕过 = 把回执**改名挪走**再跑。⇒ 已开 **BL-25**。
2. ★ **`_SELECT_ITEMS` 多了一个绑定参数（`:uid`）** ⇒ 所有取 session 详情的用例 **50001**，
   而 SQL 看着**完全正常**（同族：**坑 73**）。修法 = 那处改用**行内列** `i.user_id`
   （比"给该查询补一个 uid 参数"更贴合语义，也少一处将来会忘的地方）。

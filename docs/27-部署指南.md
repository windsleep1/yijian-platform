## 0. 部署就绪度结论（逐项，先给结论再动手）

| # | 检查项 | 结论 | 证据 / 说明 |
|---|---|---|---|
| 1 | `apps/api/Dockerfile` 能直接在 Render 跑吗 | ✅ **能**（已补齐 PORT） | 非 root 用户、装了 `curl`+`tzdata`、`HEALTHCHECK` 齐备。**原有缺陷：`CMD` 硬编码 `--port 8000`** ⇒ 已改为读 `${PORT:-8000}`（Render 注入 `PORT`） |
| 1a | 启动命令是 uvicorn 还是别的 | `uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}` | 外层还有 `docker-entrypoint.sh`（等依赖 → 建表 → 灌种子 → `exec` 启动） |
| 2 | 有没有健康检查端点 | ✅ **已有** | `GET /api/v1/health`（`apps/api/app/api/v1/health.py`）。返回 `status: ok/degraded` 并**逐依赖**给 `postgres`/`redis` 的 up/down |
| 3 | CORS 当前是什么 | `APP_ENV != prod` ⇒ `allow_origins=["*"]`；`== prod` ⇒ 读 `CORS_ORIGINS` 白名单 | `apps/api/app/main.py`。**实测**：预检 `OPTIONS` 会**回显 Origin**；简单请求返回 `*`。前端**不用 cookie**（全仓无 `credentials: 'include'`）⇒ 两种都可用（详见 §4.4） |
| 4 | 环境变量清单 | 见 §2.4 表 | 必填 **8 个**，其余有默认值 |
| 5 | ⚠️ **Redis 是不是必需** | ★ **必需** | `docker-entrypoint.sh` 已改成"等不到也继续启动"，但**登录/注册依赖它**（§5.2 有降级矩阵） |
| 6 | ⚠️ **容器里没有 `db/schema.sql`** | ★ **曾在真部署上崩溃，已修** | Docker 构建上下文 = `apps/api`，而 schema 在仓库根的 `db/`（本地 compose 靠卷挂载才有）。**第一次 Render 部署在这里挂了**：`cli.py` 用 `Path(__file__).resolve().parents[3]` 推断仓库根，而容器里 `__file__` = `/app/app/cli.py`，`parents` **只有 3 项** ⇒ `IndexError`。**本机路径有 8 层，所以本机永远复现不出来。** 已修（越界的那一级跳过）+ 20 条用例 + 变异验证。现在容器里会打印`镜像内无 schema.sql，但目标库已就绪（users）⇒ 跳过 init-db（预期）` |
| 6b | ★ 若**忘了**先跑 §1.3 会怎样 | **大声失败**（不是静默跑一个没表的服务） | `init-db` 会返 **1** 并打印可照做的修法（`apply-schema.py --url ... --yes`）⇒ Render 把这次部署标记为**失败**。判据：**别让「前置条件没满足」和「前置条件已满足」走同一条路** |
| 7 | 前端能否在 Vercel（Root Directory = `apps/web`）构建 | ✅ **路径已被 CI 验证** | CI 用**同样的命令、同样的工作目录**跑 `npm run build`（`.github/workflows/ci.yml` 的 `frontend-web` job）。`packages/api-core` 是**纯 TS、零依赖**，靠 tsconfig `paths` 解析到 `../../packages/api-core/src`，不需要额外安装 |
| 8 | ⚠️ **`APP_ENV=prod` 会让登录用不了** | ★ 见 §4.5 | `SMS_PROVIDER=mock` 的验证码**只在非生产环境回显** ⇒ `prod` 下拿不到验证码 |

## 1. Neon（PostgreSQL）

### 1.1 注册并建项目

1. 打开 <https://neon.com>（旧域名 `neon.tech` 会跳转）。
2. 点右上角 **Sign Up**，选 **Continue with GitHub**（或 Google / 邮箱）。授权后进入 Console。
3. 首次进入会让你建**第一个项目**（Project），填三项：
   - **Project name**：`yijian`
   - **Postgres version**：用默认（16 或更高都行）
   - **Region**：选 **Singapore (ap-southeast-1)** 或 **AWS Asia Pacific (Singapore)** —— 离国内和 Render 的新加坡节点都近
4. 点 **Create project**。等 10~20 秒，出现 **Connection string** 弹窗。

### 1.2 拿到连接串

在弹窗（或 Dashboard → **Connection string** 区块）里：

1. **Driver/语言**下拉选 **PostgreSQL**（**不要**选 Prisma / Node.js 之类，那些会加参数）。
   - 其实**随便选哪个都行**，因为我们的代码会把连接串归一（§4.1），选 PostgreSQL 只是少几层误解。
2. 需要显式打开 **Show password**（默认是隐藏的）。
3. 复制整条连接串。它长这样：

```
postgresql://neondb_owner:AbCdEf123456@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
```

> ★ **就复制这一条，不要再改它。** 不需要手动把 `postgresql://` 改成 `postgresql+asyncpg://`，
> 也不需要删 `?sslmode=require` —— 代码会自动处理（§4.1 说清了为什么）。

4. 顺手记下**这条串属于哪个分支**：Neon 默认给你 `main` 分支的 `neondb` 库，够用。

### 1.3 建表 + 应用迁移（**最关键的一步**）

Neon 给你的是**空库**：没有表、没有角色权限种子。项目的表结构全在 `db/schema.sql`，
后续变更在 `db/migrations/*.sql` —— 这两样都要灌进去。

**用项目自带的脚本**（只需要 Python + `asyncpg`，**不需要** psql）：

```bash
# 1) 进仓库根目录
cd yijian-platform

# 2) 装唯一依赖（如果用的是项目的隔离 venv，这一步可跳过）
python -m pip install asyncpg

# 3) 先"预演"一次 —— 只打印将要做什么，不碰数据库
python tools/deploy/apply-schema.py --url "把你在 1.2 复制的连接串粘到这里"
```

预演应当输出（**不会连接数据库**）：

```
[apply] 目标库：ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb
[apply] 计划：schema.sql + 5 个迁移
[apply] —— 预演结束（加 --yes 才真的执行）。
```

> ★ 预演里只显示**主机 + 库名**，**不回显口令** —— 所以这段输出可以随便贴给人看。

确认"目标库"那一行**就是你刚建的那个**，再加 `--yes` 真跑：

```bash
python tools/deploy/apply-schema.py --url "连接串" --yes
```

**成功的样子**（顺序、数字都要对上）：

```
[apply] 目标库：ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb
[apply] 计划：schema.sql + 5 个迁移
[apply] schema：执行｜迁移：执行
[apply] 执行 schema.sql …
[apply] schema 完成：public 下 40 多张表/视图
[apply] 迁移 20260917-01-locked-version-and-viewer-exam-read.sql …
[apply] 迁移 20260918-01-exam-mass-question-loss-threshold.sql …
[apply] 迁移 20260919-01-exams-drop-archived-status.sql …
[apply] 迁移 20260919-02-dictionaries-status-check.sql …
[apply] 迁移 20260929-01-judge-answer-canonical.sql …
[apply] 自检：public.users = users
```

★ **最后一行 `public.users = users` 就是判据** —— 不是"命令没报错"，而是**表真的在了**。

**常见报错与对策**

| 报错 | 原因 / 对策 |
|---|---|
| `✗ 连不上数据库：…` | ① 连接串抄漏了字符；② Neon 项目在休眠（首连要几秒，重试一次）；③ 口令里有特殊字符被聊天工具转义了 |
| `✗ 目标库里已经有 public.users ⇒ 拒绝执行` | **这是安全闸，不是 bug。** 说明这个库已经建过表了。确认目标没错、且你只想补跑迁移 ⇒ 加 `--force-migrations` |
| `permission denied to create extension "pg_trgm"` | 你用的 role 不是库的 owner。Neon 默认给 `neondb_owner`，用控制台**复制**的那条串就是它 |

> ⚠️ **不要重复跑 `--yes`。** `db/migrations/` 里有几条**不幂等**（重复应用会报错或改错数据），
> 所以脚本在检测到"已经有表"时会**直接拒绝**。

### 1.4 在 Neon 控制台确认一次

1. Neon Console → 左侧 **Tables**（有些版本叫 **SQL Editor** → 选 `neondb` 库）。
2. 能看到 `users`、`roles`、`questions`、`practice_sessions` 等表 ⇒ 第 1.3 步生效了。
3. （可选）打开 **SQL Editor**，粘这一句并 Run：

```sql
SELECT code, name FROM roles ORDER BY sort_no;
```

应当能看到角色列表（至少包含 `super_admin` / `viewer` 等）。
**看不到 ⇒ schema 没灌进去**，回 1.3 重来。

### 1.5 （可选）灌题库种子

**这一步不做也能部署成功**，只是应用起来后"练习"页会是**空题库**（每个章节 0 题），
而"错题本"页会是空列表。

要填的话，在**有应用的容器之后**最省事（见 §2.6），或者本地：

```bash
# 需要先把工程依赖装好（项目根目录）
pip install -r apps/api/requirements.txt
# 让 CLI 指向 Neon：设 DATABASE_URL，然后
python -m app.cli seed-questions      # 13MB 的种子，首次约 1~3 分钟
```

⚠️ `seed-questions` 会读 `data/seed/questions.sql`（13 MB）。**它是幂等的吗？**
—— 会先按章节清掉再灌（属于"按批次清场"），所以**重复执行是安全的**，
但**别在别人正在用的库上跑**。

## 2. Render（后端 API · Docker）

### 2.1 注册

1. 打开 <https://render.com>，点 **Get Started** → **GitHub** 授权登录。
2. 首次会让你选"授权哪个仓库"：选 **Only select repositories** → 勾选本项目的仓库。
   （选 All repositories 也行，只是权限更大。）

### 2.2 新建 Web Service

1. 右上角 **New +** → **Web Service**。
2. 选 **Build and deploy from a Git repository** → **Next**。
3. 在列表里点你的仓库右边的 **Connect**。
   - 列表里没有？点 **Configure account** 去 GitHub 补授权。

### 2.3 填表单（**逐项照抄，注意加粗的几项**）

| 字段 | 填什么 |
|---|---|
| **Name** | `yijian-api` |
| **Region** | **Singapore**（离 Neon 与国内都近） |
| **Branch** | `main` |
| **Root Directory** | **`apps/api`** ← 关键 |
| **Runtime**（Language） | 选 **Docker** |
| **Dockerfile Path** | `Dockerfile`（相对 Root Directory） |
| **Docker Build Context Directory** | `apps/api` |
| **Instance Type** | **Free** |
| **Health Check Path** | **`/api/v1/health`** ← 关键 |
| **Auto-Deploy** | `Yes` |

> ⚠️ **"Root Directory" 与 "Dockerfile Path" 是两个字段，别填反。**
> Root Directory 是"从仓库的哪个子目录开始"，Dockerfile Path 是"在这个子目录里，
> Dockerfile 叫什么"。填成 `/apps/api/Dockerfile`（带斜杠、带目录）会被判为找不到文件。

> ℹ️ Render 会把平台分配的端口放在环境变量 **`PORT`** 里（免费档默认 10000）。
> 本项目的启动命令**已经读它**（`--port ${PORT:-8000}`），你**不用**手工指定端口，
> 也**不要**把 `8000` 填进任何"端口"字段——Render 没有这个字段，端口由 `PORT` 决定。

### 2.4 环境变量（**在 Create 之前填**）

在同一页面往下滚到 **Environment Variables**，点 **Add Environment Variable** 逐个加。
下表按"必填 → 建议"排序：

| 变量名 | 值从哪来 | 填到哪 |
|---|---|---|
| `APP_ENV` | 填 **`dev`** | ⚠️ **先不要填 `prod`** —— 原因见 §4.5（mock 验证码在 prod 不回显 ⇒ 登录不了）。等接了真短信再改 |
| `DATABASE_URL` | Neon 控制台复制的那条（§1.2），**原样粘贴** | Render → Environment Variables |
| `REDIS_URL` | Upstash 控制台复制的 `rediss://…`（§5.2 教怎么拿） | 同上。★ **必填**：登录/注册依赖它 |
| `JWT_SECRET` | 本机跑 `python -c "import secrets;print(secrets.token_urlsafe(48))"` | 同上。**别用默认值** |
| `SMS_PROVIDER` | 填 `mock` | 同上（只有 mock 可用，另两个通道尚未接入） |
| `ADMIN_INIT_PHONE` | 你想要的超管手机号，如 `13800000000` | 同上。容器启动时**幂等**地建/修这个超管 |
| `ADMIN_INIT_PASSWORD` | 你自己定，**至少 8 位** | 同上。⚠️ 少于 8 位会被**静默跳过**（日志里有一行 `must be >= 8 chars; skipping`） |
| `APP_TIMEZONE` | `Asia/Shanghai` | 同上（有默认值，写出来更清楚） |
| `DB_POOL_SIZE` | `5` | 同上。免费档省连接（默认 20 对这个小站是浪费，也更容易被限流） |
| `DB_MAX_OVERFLOW` | `2` | 同上 |
| `CORS_ORIGINS` | **先留空**，等 §3 拿到 Vercel 域名再回来填 | 同上。只在 `APP_ENV=prod` 时生效，所以现在留空没有副作用 |
| `SNOWFLAKE_WORKER_ID` | `1` | 同上。**只有多实例时才需要各不相同**（免费档 1 个实例） |
| `TZ` | `Asia/Shanghai` | 同上（Dockerfile 里已有，写出来便于排障） |

> ★ **哪些不用填**：`MEILI_*`（检索未接入）、`MINIO_*`（对象存储未接入）、
> `CELERY_*`（定时任务未接入）、`WECHAT_*` / `ALIPAY_*`（二期）。
> 填了也不会报错（`extra="ignore"`），但别花时间。

### 2.5 点 Create，然后看日志

点最下面的 **Create Web Service**。页面自动跳到 **Logs**。

**成功的样子**（日志里应当能看到这些行，顺序大致如下）：

```
[entrypoint] 环境: APP_ENV=dev  PORT=10000
[entrypoint] 等待 PostgreSQL ...
[cli] PostgreSQL ready
[entrypoint] 等待 Redis ...
[cli] Redis ready
[entrypoint] Redis 已就绪
[entrypoint] 确保数据库结构已就绪 ...
[cli] 镜像内无 schema.sql，但目标库已就绪（users）⇒ 跳过 init-db（**预期**）
[entrypoint] 重放 RBAC 种子（补后加角色）...
[cli] 镜像内无 schema.sql ⇒ 跳过 seed-rbac（角色/权限已随 apply-schema 灌入）
[entrypoint] 初始化超级管理员 ...
[cli] admin seeded: 13800000000
[entrypoint] 启动: sh -c uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
INFO:     Uvicorn running on http://0.0.0.0:10000 (Press CTRL+C to quit)
```

★ **那两条「跳过」是正常的**（不是错误）：schema 已经由 §1.3 灌进 Neon 了，
`db/` 目录也不在 Docker 构建上下文里。**看到它们不用管。**

⚠️ 但如果看到的是这一条，说明**你还没做 §1.3**（容器会以退出码 1 结束、部署标记为失败）：

```
[cli] ✗ 目标库里没有 public.users，而镜像里也没有 db/schema.sql ⇒ 这个库还没初始化。
[cli]   修法（在**本机**跑一次，见 docs/27 §1.3）：
[cli]       python tools/deploy/apply-schema.py --url "<Neon 连接串>" --yes
```
这是**故意**的：宁可让部署**明确失败**，也不要让一个**没有任何表**的 API 正常启动 ——它 `/api/v1/health` 还能返 200（`degraded`），而每个真实请求都 500，是最难查的一种「活着但没用」。

**如果 Redis 没配好**，你会看到：

```
[entrypoint] ⚠️ Redis 不可用 —— **继续启动**（降级：...）
```

此时**容器仍然会起来**，`/api/v1/health` 会报 `degraded`。
但**登录/注册会 503** —— 回去解决 Redis（§5.2）。

### 2.6 验证后端真的活着

服务卡（Service 页）上方会显示域名，形如 `https://yijian-api-xxxx.onrender.com`。
**记下它**，第 3 步要用。

```bash
# ① 健康检查（应当返回 JSON，status 是 ok）
curl -s https://<你的服务>.onrender.com/api/v1/health
```

期望输出（格式化后）：

```json
{"code":0,"message":"ok","data":{"status":"ok","app":"一建通","version":"0.2.0","env":"dev",
 "dependencies":{"postgres":"up","redis":"up"},"sms_provider":"mock"}, ...}
```

★ **判据是两个依赖都要 `up`**（`postgres` 和 `redis`）——
只看到 `status: ok` 不够，`degraded` 也是 200。

```bash
# ② 顺手看一眼接口文档（能打开说明路由与静态资源都正常）
#    浏览器打开： https://<你的服务>.onrender.com/docs
```

> ⏱️ **免费档会休眠**：15 分钟没流量就挂起，下次请求要 **50 秒上下**才响应。
> 第一次访问 `/health` 转圈是正常的，别以为部署挂了。
>
> **（可选）想减轻冷启动**：Render 免费档不能设"保持唤醒"，但可以用
> <https://uptimerobot.com> 之类的免费监控每 10 分钟打一次 `/api/v1/health`。
> ⚠️ 这违反 Render 免费档的"按需唤醒"精神，是否使用你自己权衡。

**（可选）灌题库种子**：Service 页 → 右上角 **Shell** → 输入：

```bash
python -m app.cli seed-questions
```

## 3. Vercel（前端 · 两个项目）

要建**两个** Vercel 项目：`apps/web`（C 端）和 `apps/admin`（管理端）。
仓库里**没有根 `package.json`**，所以**必须**分别建，不能从仓库根一键导入。

### 3.1 注册

1. 打开 <https://vercel.com>，点 **Sign Up** → **Continue with GitHub**，授权。
2. 进入 Dashboard。

### 3.2 建 C 端项目（`apps/web`）

1. 点 **Add New…** → **Project**。
2. 在 **Import Git Repository** 列表里找到本项目 → 点 **Import**。
   - 没有？点 **Adjust GitHub App Permissions** 去补授权。
3. 在配置页里改**三项**：

| 字段 | 填什么 |
|---|---|
| **Project Name** | `yijian-web`（域名会变成 `yijian-web-xxx.vercel.app`） |
| **Framework Preset** | `Next.js`（自动识别，保持不动） |
| **Root Directory** | 点 **Edit** → 选 **`apps/web`** ← **关键** |

4. 展开 **Environment Variables**，加一条：

| 变量名 | 值 | 说明 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE` | `https://<你的 Render 服务>.onrender.com/api/v1` | ★ **结尾必须是 `/api/v1`**，不能只到域名 |

5. 点 **Deploy**。等 1~3 分钟（首次要装依赖）。

**成功的样子**：出现 "Congratulations!" + 一张预览图，域名如
`https://yijian-web-xxxx.vercel.app`。**记下它。**

### 3.3 建管理端项目（`apps/admin`）

**完全重复 §3.2**，只改两处：

- **Project Name**：`yijian-admin`
- **Root Directory**：`apps/admin`

环境变量**同名同值**（`NEXT_PUBLIC_API_BASE` = 同一个 Render 地址）。

> ★ 两个项目**必须同名同值**填 `NEXT_PUBLIC_API_BASE` —— 它们打的是同一个后端。

### 3.4 回填 CORS（只有 `APP_ENV=prod` 才需要）

## 4. 三个已知坑的处理方案

### 4.1 Neon 连接串格式（`postgresql://` vs `postgresql+asyncpg://`）

**结论：什么都不用做，原样粘贴即可。** 代码里做了兼容，见
`apps/api/app/core/config.py::normalize_database_url`（纯函数，有 17 条用例钉着）。

它做三件事：

| # | 动作 | 不做会怎样 |
|---|---|---|
| ① | 把 `postgres://` / `postgresql://` / `postgresql+psycopg2://` 统一成 `postgresql+asyncpg://` | SQLAlchemy 会去找 **psycopg2** 驱动 ⇒ 现场报 `No module named 'psycopg2'`（而依赖清单里根本没有它） |
| ② | 摘掉 `sslmode` / `channel_binding` / `target_session_attrs` | 这些是 **libpq** 的参数，**asyncpg 不认**。SQLAlchemy 的 asyncpg 方言会把 URL 上的查询参数当连接参数转发 ⇒ 报"传了它没有的关键字" |
| ③ | 看到 `sslmode=require` ⇒ 把 `db_ssl_require` 置 `True`，两处连接（SQLAlchemy 池 + 裸 asyncpg）**都带上** `ssl` | Neon **强制 TLS** ⇒ 不加密直接连不上 |

> ★ 为什么 ②③ 要**拆开**做，而不是简单地把 `sslmode=require` 就地改写成 `ssl=require`：
> `ssl` 这个键在 **DSN 字符串**里能不能被识别，取决于 asyncpg 的 DSN 解析器 ——
> 那是一件**本机没有托管 PG 就验证不了的事**。
> "摘掉 + 用连接参数显式传"在**两种假设下都对**，所以选它。
> （判据：不赌一个自己无法证伪的默认行为。）

**手动核对**（可选）：本地跑一句就能看到归一结果

```bash
python -c "
import sys; sys.path.insert(0,'apps/api')
from app.core.config import normalize_database_url
print(normalize_database_url('postgresql://u:p@h.neon.tech/neondb?sslmode=require&channel_binding=require'))
"
# 期望： ('postgresql+asyncpg://u:p@h.neon.tech/neondb', True)
```

### 4.2 数据库初始化：最简执行路径

**推荐路径 = §1.3 的 `apply-schema.py`**（只要 Python + `asyncpg`）。

备选路径与取舍：

| 方案 | 优点 | 缺点 |
|---|---|---|
| ✅ **`tools/deploy/apply-schema.py`**（推荐） | 只要 Python；**有预演**；有"已有表就拒绝"的安全闸；自动按序跑迁移；输出可读 | 需要 `pip install asyncpg` |
| `psql -f`（CI 用的那条） | 不用装 Python 包 | **要求本机装了 psql**（Windows 默认没有）；要自己写循环跑迁移 |
| Neon 控制台 **SQL Editor** 粘贴 | 零安装 | `schema.sql` 有 **79 KB / 1552 行**，粘贴体验差；5 个迁移要**开 5 次**；顺序容易错 |

> ⚠️ **无论哪种方案，顺序都是：`db/schema.sql` 先 → 再按文件名字典序跑 `db/migrations/*.sql`。**
> 反了会报"表不存在"。

### 4.3 首次部署顺序（**不能颠倒**）

```
① Neon 建库                    ← 拿到 DATABASE_URL
② apply-schema.py --yes        ← 表 + RBAC 种子 + 迁移 都就位
③ Upstash 建 Redis             ← 拿到 REDIS_URL（登录必需）
④ Render 部署 API              ← 依赖 ①②③
⑤ 用 curl 验 /api/v1/health    ← 判据：postgres=up 且 redis=up
⑥ Vercel 部署 web + admin      ← 依赖 ④（要它的域名填 NEXT_PUBLIC_API_BASE）
⑦ （仅 prod）回填 CORS_ORIGINS ← 依赖 ⑥（要 Vercel 域名）
⑧ 浏览器走一遍注册/登录/练习    ← 端到端验收
```

**为什么不能颠倒（每条都有具体后果）**：

| 如果先做 | 会怎样 |
|---|---|
| 先 Render、后灌 schema | 容器启动时 `init-db` 会**建表**（如果那时 schema 文件在）或**跳过**；但 `seed-rbac` 在 Render 上**永远跳过**（文件不在构建上下文）⇒ **角色权限缺失**，注册后权限异常。而且顺序反了以后，`apply-schema.py` 会因"已有表"**拒绝执行** |
| 先 Vercel、后 Render | `NEXT_PUBLIC_API_BASE` 没有真地址 ⇒ 页面上所有请求打空 |
| 先填 `CORS_ORIGINS`、后建 Vercel | 只能填占位域名 ⇒ 前端一直 CORS 失败 |

### 4.4 CORS：两条路，以及我推荐哪条

你的记录里提到"推荐用 Vercel rewrites 代理"。我**实测之后建议走 CORS 白名单**，
理由是下面这条实测结论 —— 但两条路都给你。

**实测（本地 API，带跨域请求头打过去）**：

| 请求类型 | 后端返回 | 浏览器接受吗 |
|---|---|---|
| 预检 `OPTIONS`（带 `Authorization` 的请求必走） | `access-control-allow-origin: <回显你的 Origin>` + `allow-credentials: true` | ✅ 接受 |
| 简单请求 `GET` | `access-control-allow-origin: *` + `allow-credentials: true` | ⚠️ **只在"不带凭据"时接受** |

★ 而本项目的前端**不带凭据**：全仓 grep 不到 `credentials: 'include'`，
认证走的是 `Authorization: Bearer`（那是普通请求头，不是 Fetch 规范里的"凭据"）。
⇒ 上面两种响应**都能被浏览器接受**，跨域直连可行。

**两条路对比**

| | **A. CORS 白名单**（推荐） | **B. Vercel rewrites 代理** |
|---|---|---|
| 改动 | **零代码**（`APP_ENV=prod` + `CORS_ORIGINS` 即可，代码已支持） | 要改两个 `next.config.mjs`（加 `rewrites`） |
| 与现有设计的关系 | 一致 —— `next.config.mjs` 里明确写着"**不做 rewrite 代理**，前端直连才看得见真实的 CORS / 401 / trace_id 行为" | **推翻**了那条已有决策，需要在注释里说明为什么改 |
| 代价 | 前端要知道后端域名（就是 `NEXT_PUBLIC_API_BASE`，本来就要知道） | 多一跳代理；Render 冷启动时 Vercel 侧可能先超时；本地开发没有这条代理 ⇒ **本地与线上路径不一致** |
| 适合 | 就是这个项目 | 后端不方便改 CORS 的场合 |

**走 B 的话怎么改**（如果你仍偏好）：

```js
// apps/web/next.config.mjs（apps/admin 同款）
const nextConfig = {
  reactStrictMode: true,
  eslint: { ignoreDuringBuilds: true },
  async rewrites() {
    return [
      { source: "/api/v1/:path*", destination: `${process.env.API_ORIGIN}/api/v1/:path*` },
    ];
  },
};
```

再给 Vercel 加一条**非 `NEXT_PUBLIC_`** 的 `API_ORIGIN`（代理在服务端跑，不需要暴露给浏览器），
并把 `NEXT_PUBLIC_API_BASE` 改成 `/api/v1`。
⚠️ **注意三点**：① 后端仍然要允许来源（CORS 中间件对同源代理请求不生效，
但**浏览器同源**了所以不触发 CORS）—— 所以 `CORS_ORIGINS` 可以留空；
② `NEXT_PUBLIC_*` 是**构建期内联**，改完必须 Redeploy；
③ 本地 `npm run dev` **没有**这条代理，行为与线上不同（这是 B 的主要代价）。

### 4.5 ★ `APP_ENV=prod` 会让"登录"用不了（**这条最容易被忽略**）

`apps/api/app/services/sms_service.py`：

```python
    dev_code: str | None = None
    if settings.sms_provider == "mock":
        logger.info("[MOCK SMS] phone=%s scene=%s code=%s", phone, scene, code)
        if not settings.is_prod:      # ← 关键
            dev_code = code
```

也就是说：**`SMS_PROVIDER=mock` 时，验证码只在"非生产环境"回显给前端。**
而另两个通道（阿里云 / 腾讯云）**代码里还没接**（`_dispatch_real_sms` 直接
`raise NotImplementedError`）。

⇒ 组合一下：

| `APP_ENV` | `SMS_PROVIDER` | C 端注册/登录 |
|---|---|---|
| `prod` | `mock` | ❌ **拿不到验证码 ⇒ 注册/登录全废** |
| `prod` | `aliyun`/`tencent` | ❌ 抛 `NotImplementedError` |
| **`dev`**（或 `staging`） | `mock` | ✅ 验证码回显在接口响应里，能用 |

★ **所以作品集部署的正确取值是 `APP_ENV=dev` + `SMS_PROVIDER=mock`**，
并把"验码回显"当成**有意的演示特性**（它让评审者不用真短信就能登录）。

**要真正上生产**（比如你以后接了自己的用户）需要：
① 申请一个短信服务并接入 `_dispatch_real_sms`（约 20 行）；② 那时才把 `APP_ENV` 改成 `prod`。

> ⚠️ 注意 `APP_ENV=dev` 的**副作用**：`APP_DEBUG` 默认 `True` ⇒ 日志级别是 DEBUG，
> 日志会偏多。想要安静一点就额外设 `APP_DEBUG=false`。
> 另外 `is_prod=False` ⇒ `JWT_SECRET` 的"必须 ≥32 位"校验**不触发** ——
> **仍然请设一个真随机值**，否则任何人都能伪造 token。

### 5.2 Redis：**必需**，用 Upstash 免费档

**为什么必需**（2026-10-01 实测核对的降级矩阵）：

| 用途 | Redis 挂掉时 | 出处 |
|---|---|---|
| 限流 | **放行**（只记日志） | `core/deps.py` |
| RBAC 权限缓存 | **回源数据库** | `services/rbac_service.py` |
| **短信验证码** | **503 `unavailable`** ⇒ 注册/登录用不了 | `services/sms_service.py` |
| **登录锁定** | 抛异常 ⇒ 登录失败 | `services/auth_service.py` |

> ⚠️ 顺带修正一处**过期注释**：`app/db/base.py` 原先写着"Redis 不可用时不阻塞启动
> （降级：限流关闭、**验证码走内存 + 日志**）"。其中"**验证码走内存**"是**不成立的**——
> 全仓没有任何内存实现，`_send_code` / `verify_code` 只读写 Redis。
> 本地之所以"看起来能降级"，是因为本地跑的是 `tools/local-verify/serve_fake_redis.py`
> —— 那是一个**真的 Redis 服务**。注释已按实际矩阵改正。

**拿一个 Upstash Redis（免费）**：

1. 打开 <https://upstash.com> → **Sign Up**（GitHub / Google 都行）。
2. Dashboard → **Create Database**：
   - **Name**：`yijian-redis`
   - **Type**：`Regional`
   - **Region**：**Singapore**（和 Render / Neon 对齐）
   - **TLS**：**开启**（默认开）
3. 建好后进数据库详情页，往下找 **Connect to your database** → 选 **Node.js** 或 **ioredis**
   （**任何语言都行**，我们只要那个 URL）。
4. 复制 **`REDIS_URL`**，它长这样：

```
rediss://default:AbCdef123456@xxxxx-12345.upstash.io:6379
```

★ **一定是 `rediss://`**（两个 s，= TLS）。本项目用的 `redis.asyncio.from_url`
支持 `rediss://`，直接粘到 Render 的 `REDIS_URL` 即可。

5. 回 Render → **Environment** → 加 `REDIS_URL` = 上面那条 → **Save**（自动重新部署）。

**验证**：`curl .../api/v1/health` 里 `"redis":"up"`。

### 5.3 ★ `NEXT_PUBLIC_*` 是**构建期内联**的

Next.js 会在 `next build` 时把 `process.env.NEXT_PUBLIC_API_BASE` **替换成字面量**。
⇒ **改了环境变量不会生效，必须重新部署（Redeploy）**。

- Vercel → 项目 → **Deployments** → 最新那条右侧 **⋯** → **Redeploy**
- 勾 **Use existing Build Cache** 会**不生效**（缓存里还是旧值）⇒ 先 **uncheck** 或选
  "Redeploy without cache"

**判据**：打开线上页面 → F12 → Network → 看请求打的是哪个域名。
还是 `localhost:8000` 或旧域名 ⇒ 没重新构建。

### 5.4 Neon 免费档

| 限制 | 影响 | 对策 |
|---|---|---|
| 计算资源空闲后自动挂起 | 首连接慢几秒 | `pool_pre_ping=True` 已开，会重连 |
| 存储 / 计算时长有额度 | 作品集流量远够 | —— |
| **连接数有限** | 连接池开太大容易被限 | `DB_POOL_SIZE=5` / `DB_MAX_OVERFLOW=2`（§2.4 已写） |
| 有 `-pooler` 端点 | 走 PgBouncer 事务模式 | 本项目**用直连**（非 pooler）端点。因为 asyncpg 默认用**预备语句**，而事务模式的连接池会打乱会话状态；走 pooler 需要额外关掉语句缓存。**免费档用直连更省心** |

| 100 GB/月 带宽、100 次/天 部署 | 作品集远够 |
| 是否商用有条款限制 | 纯作品集展示没问题 |

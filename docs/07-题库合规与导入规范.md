# 07 · 题库合规与导入规范

> 这一章决定了产品能不能长期活下去。**技术可以迭代，版权事故不可逆。**

---

## 1. 合规红线（不可协商）

| 红线 | 说明 |
|---|---|
| **禁止抓取受版权保护的真题原文** | 历年真题的题目表述、选项、解析通常由命题机构或出版方享有权利。未经授权不得复制、改编后使用。 |
| **禁止绕过 robots.txt / 反爬机制** | 即使目标站未明确禁止，也不得使用技术手段突破访问限制。 |
| **禁止使用"网友整理版""盗版资料"** | 来源不可追溯即视为不可用。用户上传的资料同样需要其声明权利来源。 |
| **禁止将 AI 生成题直接标为"真题"** | AI 辅助产出的题必须标 `source_type='ai_assisted'`，且必须经人工复核后才能发布。 |
| **禁止未标注来源** | 每道题必须有 `source_type`；非自有内容必须填 `source_name` 与 `source_license`。 |

### 法律依据速查

| 法规 | 相关条款 | 对本项目的约束 |
|---|---|---|
| 《著作权法》 | 第 10 条、第 24 条 | 试题作为文字作品受保护；"合理使用"不覆盖商业性题库 |
| 《信息网络传播权保护条例》 | 第 2 条、第 23 条 | 通过网络提供他人作品需授权；平台方可能承担连带责任 |
| 《著作权法》 | 第 24 条第 1 款第 6 项 | 教学科研少量使用可免责，但**商业运营不适用** |
| 《网络安全法》 | 第 27 条 | 禁止非法侵入、干扰他人网络 |
| 《个人信息保护法》 | 第 13、14 条 | 用户导入资料含他人信息时需授权 |

> 以上为一般性提示，具体项目请由法务出具正式意见。**上线前必须完成一次法务审查。**

## 2. 合规来源矩阵

| 来源 | `source_type` | 可用性 | 要求 | 风险 |
|---|---|---|---|---|
| **自有教研原创** | `self` | ✅ 首选 | 教研产出，签署职务作品协议（权利归公司） | 无 |
| **授权采购题库** | `authorized` | ✅ 推荐 | 书面合同明确授权范围（期限/渠道/是否可改编/是否可再许可） | 低（需守住合同边界） |
| **公开可用内容** | `public` | ✅ 可用 | 政府公开文件、已过保护期作品、CC 授权内容、官方公开考纲 | 低（需逐条核对许可类型） |
| **用户合法导入** | `user_import` | ⚠️ 需审核 | 用户声明其有权提供；平台审核后入库 | 中（需免责声明 + 审核留痕） |
| **AI 辅助原创** | `ai_assisted` | ⚠️ 需复核 | AI 生成题干，人工核对专业正确性与表述 | 中（必须人工复核） |
| **网络公开真题** | ❌ 禁止 | ❌ | — | **高（下架 + 赔偿）** |
| **网友整理/盗版资料** | ❌ 禁止 | ❌ | — | **高** |

### 2.1 "公开可用"的判定清单

满足以下**全部**条件才可标为 `public`：

- [ ] 内容来源于政府机关官方发布（如住建部公告、考纲原文）
- [ ] 或作者已声明放弃权利 / 采用 CC BY / CC0 等允许商用的许可
- [ ] 或作品已过著作权保护期（作者死后 50 年）
- [ ] 保存了来源 URL 与抓取时间（`source_name` + 归档快照）
- [ ] 使用方式未超出许可范围（注意 CC BY-NC 不可商用）

### 2.2 授权采购的合同必查项

签订题库采购合同时，必须逐项确认：

1. **授权范围**：是否包含信息网络传播权？是否可改编、拆分、组合成新卷？
2. **授权期限**：起止日期，到期后已购题库是否需下架？
3. **授权渠道**：是否限定渠道（仅网站/含小程序/含 APP）？
4. **地域范围**：中国大陆？
5. **独家性**：是否独家？非独家则需评估同质化竞争
6. **转授权**：能否再许可给加盟商/合作方？
7. **违约责任**：对方内容侵权导致平台受损的赔偿条款
8. **凭证留存**：合同编号写入 `questions.source_license`，合同原件由法务归档

## 3. 题库建设路线（合规前提下达到 10000+）

| 阶段 | 目标题量 | 构成 | 说明 |
|---|---|---|---|
| **第 1 个月（冷启动）** | 6000 | `self` 原创仿真题 6000 | 按考纲知识点覆盖，产出用 `db/seed/gen_seed_questions.py` 的模式 + 教研审校 |
| **第 2–3 月** | 12000 | + 授权采购 4000、+ 公开考纲衍生 1000、+ 用户投稿 1000 | |
| **第 4–6 月** | 20000+ | + 持续原创 5000、+ 授权增量 3000 | 教研团队稳定产出 |

### 3.1 原创仿真题的合规要点

自有原创题**不需要**是真题，但必须：

- ✅ 严格覆盖考纲知识点（`knowledge_point_id` 必填）
- ✅ 题干表述原创，不得照搬教材原文长段落（引用法规原文属合理，需注明出处）
- ✅ 引用法规条文原文是可以的（法律文本不受著作权保护），但不得引用他人编写的解读
- ✅ 明确标注 `source_type='self'`
- ✅ 题目本身具备考试价值（难度、干扰项设计合理）

### 3.2 教研产出流程

```
教研按知识点清单认领 → 撰写题干/选项/答案/解析 → 自检
  → 提交（status=draft → reviewing）
  → 交叉审核（另一位教研，status=reviewing → published / rejected）
  → 发布并推送搜索索引
```

**交叉审核是硬性要求。** 一人写一人审，是保证专业正确性的最低成本手段。

## 4. 导入规范

### 4.1 支持格式

| 格式 | 适用 | 说明 |
|---|---|---|
| `.xlsx` | 教研日常录入 | 推荐，支持富文本受限，图片用 URL 引用 |

### 4.3 完整导入流程

```
① 上传          POST /admin/imports/upload
                 → 校验文件类型/大小/编码 → 创建 import_batches(status=pending)
                 → 返回 batch_id（此时未写任何题目）

② 解析校验      POST /admin/imports/{id}/validate      [异步]
                 status: pending → parsing → validating
                 逐行执行：
                   - 字段完整性（必填项）
                   - 枚举合法性
                   - 外键存在性（科目/章节/知识点编码是否存在）
                   - 题型-选项一致性（单选必须有且仅有 1 个正确答案）
                   - 答案合法性（multiple 的字必须都在选项里）
                   - content_hash 去重 → 标记 duplicate
                   - 合规校验：source_type != self 时 source_name 是否填写
                   - 与库内已有题比对 → 标记将 insert / update
                 写 import_items(每行一条：insert/update/skip/error/duplicate + message)
                 统计：total / success / failed / duplicate / updated
                 status → done（此阶段完成，可终止不产生副作用）

③ 人工确认      教研在后台查看校验报告，决定：
                   - 全部导入
                   - 只导入 insert（跳过 update）
                   - 修正错误行后重新上传

④ 执行导入      POST /admin/imports/{id}/execute
                 status: done → importing
                 分批（每批 500 行）：事务内
                   INSERT INTO questions (...) 
                   ON CONFLICT (content_hash) WHERE is_deleted = false 
                   DO UPDATE SET ... , version = questions.version + 1, updated_at = now()
                   
                   同时：写 question_options、question_versions、content_change_logs(batch_id)
                 推送 Meilisearch（异步）
                 status → done，更新各项计数

⑤ 发布          POST /admin/imports/{id}/publish
                 批量将 status 从 draft → published
                 （推荐「先入库草稿 → 教研抽样验收 → 再批量发布」，避免污染线上题库）

⑥ 回滚          POST /admin/imports/{id}/rollback      [需 question:rollback 权限]
                 遍历 import_items：
                   action='insert' → 软删除对应 question
                   action='update' → 从 question_versions 还原到导入前版本
                 删除 Meilisearch 索引
                 status → rolled_back，写审计日志
```

### 4.5 去重算法

见 `docs/03-数据库设计.md` 第 4.1 节（归一化 → SHA-256 → 部分唯一索引）。

**三级去重策略**：

| 级别 | 方法 | 处理 |
|---|---|---|
| **L1 精确去重** | `content_hash` 完全一致 | 自动 `duplicate`，跳过或更新 |
| **L2 近似去重** | 题干 simhash / trigram 相似度 > 0.92 | 标记 `suspicious`，人工确认 |
| **L3 语义去重（后期）** | 题干向量余弦相似度 > 0.90 | 教研大屏预警 |

L2/L3 通过 `GET /admin/questions/duplicates` 暴露给教研：

```sql
-- L2 近似重复检测（trigram 相似度）
SELECT a.id AS id_a, b.id AS id_b,
       similarity(a.stem, b.stem) AS sim
FROM questions a
JOIN questions b
  ON a.subject_id = b.subject_id
 AND a.id < b.id
 AND a.stem % b.stem                      -- 走 idx_questions_stem_trgm
WHERE a.subject_id = $1
  AND similarity(a.stem, b.stem) > 0.92
  AND a.is_deleted = false AND b.is_deleted = false
ORDER BY sim DESC
LIMIT 100;
```

## 5. 审核与发布工作流

```
                 ┌──────────┐
   新建/导入 ───▶ │  draft   │ 草稿：可任意编辑
                 └────┬─────┘
                      │ 提交审核
                 ┌────▼──────┐
                 │ reviewing │ 待审：锁定编辑，审核人可改
                 └────┬──────┘
           通过 ┌────┴─────┐ 驳回
        ┌──────▼───┐  ┌────▼──────┐
        │published │  │ rejected  │ 驳回：附原因，退回作者
        └────┬─────┘  └────┬──────┘
             │             │ 修改后重提
             │ 下架         └──────▶ draft
        ┌────▼─────┐
        │ archived │ 归档：不出现在任何练习/组卷中，但保留数据
        └──────────┘
```

| 状态 | 可搜索 | 可抽题 | 可编辑 | 说明 |
|---|---|---|---|---|
| `draft` | ❌ | ❌ | ✅ | 教研编辑中 |
| `reviewing` | ❌ | ❌ | 仅审核人 | 锁定防篡改 |
| `published` | ✅ | ✅ | ⚠️需 `question:update`，改动自动递增版本 | 线上可见 |
| `rejected` | ❌ | ❌ | ✅ | 附驳回原因 |
| `archived` | ❌ | ❌ | ✅ | 已废弃 |

### 5.1 审核检查清单（教研必过）

- [ ] 题干表述清晰无歧义，无错别字
- [ ] 选项互斥、无重复、无"以上都对"这类无效选项
- [ ] 答案正确（对照规范/教材核对）
- [ ] 解析逻辑完整，能说明为什么错、为什么对
- [ ] 已关联正确的章节与知识点
- [ ] 难度标注合理（1–5）
- [ ] 合规：来源已标注，`source_type` 正确

### 5.2 题目质量自动预警

每日定时任务扫描 `question_stats`：

```sql
-- 异常题预警
SELECT q.id, q.subject_id, q.type, s.attempt_count, s.correct_rate,
  CASE
    WHEN s.attempt_count >= 200 AND s.correct_rate < 0.10 THEN 'too_hard'
    WHEN s.attempt_count >= 200 AND s.correct_rate > 0.97 THEN 'too_easy'
    WHEN s.discrimination < 0.05 AND s.attempt_count >= 300  THEN 'no_discrimination'
    WHEN s.report_count >= 5                                  THEN 'flagged'
  END AS flag
FROM questions q
JOIN question_stats s ON s.question_id = q.id
WHERE q.status = 'published' AND q.is_deleted = false
  AND (
    (s.attempt_count >= 200 AND (s.correct_rate < 0.10 OR s.correct_rate > 0.97))
    OR (s.discrimination < 0.05 AND s.attempt_count >= 300)
    OR s.report_count >= 5
  );
```

结果写入 `questions.quality_flag`，推送给对应科目的教研复核。

**正确率 < 10%** 的题通常是答案错或题干有歧义；**正确率 > 97%** 的题是无区分度的废题。这两类题不清理，会持续损害用户对题库的信任。

## 6. 版本管理与回滚

### 6.1 三层版本体系

| 层级 | 表 | 用途 |
|---|---|---|
| **单题版本** | `question_versions` | 每次修改/发布留存全量快照 → 单题回滚 |
| **批次版本** | `import_batches` + `import_items` | 一次导入的所有变更 → 整批回滚 |
| **题库基线** | `bank_versions` | 某时间点整库快照 → 重大事故整体回退 |

### 6.2 单题回滚

```python
def rollback_question_version(question_id: int, target_version: int, operator_id: int):
    """把题目恢复到指定历史版本。"""
    version_row = get_version(question_id, target_version)
    snapshot = version_row.snapshot          # 含 stem/options/answer/analysis/…

    with db.transaction():
        # 先备份当前状态（回滚本身也要可回滚）
        save_version(question_id, current_question(question_id),
                     change_log=f"回滚前自动备份", operator_id=operator_id)

        apply_snapshot(question_id, snapshot)

        bump_version(question_id)
        write_change_log(
            entity_type="question", entity_id=question_id,
            action="rollback", diff={"from": current_version, "to": target_version},
            operator_id=operator_id,
        )
    reindex_question(question_id)            # 同步搜索索引
```

### 6.3 批次回滚（见 4.3 第 ⑥ 步）

**回滚必须留痕**：谁在什么时候回滚了什么，写 `content_change_logs` 与 `audit_logs`。回滚是高危操作，需 `question:rollback` 权限 + 二次确认。

### 6.4 考题锁定

试卷发布后，其包含的题目**内容快照写入 `exams` 相关记录**，且题目修改不追溯影响已发布的卷。

```python
# 已发布试卷取题时，若题目版本与卷面记录不符，给出提示但不自动同步
def load_paper(exam_id):
    for eq in exam_questions(exam_id):
        q = get_question(eq.question_id)
        if q.version != eq.locked_version:
            logger.warning(f"题目 {q.id} 已更新（v{eq.locked_version}→v{q.version}），"
                           f"试卷 {exam_id} 使用锁定版本作答")
            q = get_version(eq.question_id, eq.locked_version)   # 用锁定版本
        yield q
```

> 这是**考试类产品的严肃性要求**：一个考生昨天考了 80 分，今天你改了题的答案，他的成绩就成了悬案。所以**已考过的卷面必须锁定版本**。

## 7. 定时同步（对接外部授权题库）

```python
# tasks/sync_tasks.py — Celery Beat 每日 02:00 执行
@celery.task
def sync_authorized_bank(source_id: int):
    """
    对接授权题库方的 API，增量拉取变更。
    前提：已签订书面授权合同，且对方提供正式接口（非爬取）。
    """
    src = get_source(source_id)
    assert src.license_verified, "未验证授权，拒绝同步"

    cursor = src.last_cursor
    while True:
        batch = src.client.fetch_changes(cursor, limit=500)
        if not batch.items:
            break
        # 走标准导入管道，天然获得去重/版本/回滚能力
        execute_import(
            items=batch.items,
            source_type="authorized",
            source_name=src.name,
            source_license=src.contract_no,
            mode="upsert",
            auto_publish=src.auto_publish,     # 授权方内容可信度高可直接发布
        )
        cursor = batch.next_cursor
        save_cursor(source_id, cursor)

    # 对账：删除授权方已下架的内容
    removed = src.client.fetch_removed(since=src.last_sync_at)
    for ext_id in removed:
        q = find_by_external_id(ext_id)
        if q:
            archive_question(q.id, reason=f"授权方下架（{src.name}）")
```

**同步四原则**：

1. **只走正式接口，不爬网页** —— 爬取违反合同与 robots，且对方改版即断
2. **复用标准导入管道** —— 不写第二套逻辑，天然获得去重、版本、回滚
3. **自动发布需谨慎** —— 仅对合同明确保障质量的来源开启 `auto_publish`
4. **下架要同步** —— 对方撤权的内容必须及时归档，否则构成侵权

## 8. 变更日志与审计

所有涉及题库的写操作，必须写 `content_change_logs`：

| 字段 | 内容 |
|---|---|
| `entity_type` | `question` / `chapter` / `exam` / `course` |
| `entity_id` | 实体 ID |
| `action` | `create` / `update` / `publish` / `archive` / `rollback` / `delete` |

| `diff` | `{"before": {...}, "after": {...}}`，只记变化字段 |

| `created_at` | 时间 |

**审计要求**：

- 日志**只增不改不删**（数据库层面不提供删除接口）
- 保留期 ≥ 3 年（版权纠纷可能多年后追责）
- 支持按题目 ID 反查"这道题被谁改过几次、改了什么"
- 运营后台提供检索；导出需 `system:audit` 权限

## 9. 用户投稿与举报

### 9.1 用户投稿

```
用户提交题目 → status=draft, source_type=user_import
  → 用户需勾选《内容授权声明》：
      "我确认该内容为我原创或我已获得合法授权，同意平台在授权范围内使用"
  → 教研审核（同 5.2 清单 + 合规核验）
  → 通过则发布，用户获得积分/会员天数奖励
  → 驳回则告知原因
```

**免责声明文本必须包含**：投稿人保证权利合法性、平台有权审核与删除、侵权责任由投稿人承担、平台可撤销奖励。

### 9.2 侵权举报通道

必须提供，且要快：

| 步骤 | 时限 | 动作 |
|---|---|---|
| 收到通知 | 即时 | 工单入队，责任人认领 |
| 初步核查 | 24 小时内 | 核对权利证明与涉事内容 |
| 临时措施 | 48 小时内 | 争议内容下架（`status=archived`），保留证据 |
| 完整处理 | 7 个工作日内 | 通知举报人处理结果；如成立则永久移除并追溯 |
| 留档 | — | 举报材料与处理过程归档 ≥ 3 年 |

入口：`/me/feedback` 增加"版权投诉"类型 + 法务邮箱；公告页脚固定展示投诉渠道。

## 11. 附：原创题生成器说明

`db/seed/gen_seed_questions.py` 产出**严格合规的原创仿真题**，用于：

- 技术开发与联调（不依赖真实题库）
- 单元测试与压测的基准数据
- 冷启动阶段的题库兜底

它的产出特征：

| 特征 | 说明 |
|---|---|
| `source_type` | 统一为 `self` |
| `source_name` | `内置原创仿真题库 v1` |
| `exam_year` | 不填（绝不伪造年份冒充真题） |
| `tags` | 含 `仿真题` 标签，与真实题库可区分 |
| 内容 | 基于考纲章节的知识点模板化生成，题干表述原创 |

**它不能替代教研产出。** 它的价值在于让工程开发不被题库阻塞，以及验证导入管道在 6000 题规模下的正确性与性能。

生产题库必须来自第 2 节的合规来源矩阵。

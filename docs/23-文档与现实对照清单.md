# 23 · 文档与现实对照清单（**"声称" ≠ "已验证"**）

> 建立：2026-09-26 ｜ 来源：用户 2026-09-26 建议（"列出所有『文档声称 X 但没验证过』的关键点"）
>
> **它解决的是同一族问题：没有任何东西会报错。**
> 文档说"有 X"而代码里没有 X —— 与「测试绿了但没真跑」（**假绿**）、
> 「判据写糙了把无关变化算进来」（**假红**）是**同一族**：
> **它们都不报错，只在你依赖它的那一刻失效。**
>
> 与坑 56「证据的身份」也同族：**先问"这句话被验证过吗"，再谈它是不是真的。**

---

## 1. 规则（三条）

| # | 规则 |
|---|---|
| 1 | **新加 / 修改文档时**：凡是**陈述语气**（读起来像"已经是这样"）而非**规划语气**（"计划 / 目标 / 待实现"）的断言，**要么当场验证，要么列进本清单**。 |
| 2 | **检查点**：每批收尾扫一遍（`apps/admin/docs/B端联调坑.md` 附录「一批交付收尾的固定动作」**§9**）。 |
| 3 | **只列"关键点"**：判据 = **如果它是假的，会不会有人因此做出错误决定？** 会 → 列；不会 → 不列（避免清单膨胀成噪音）。 |

**明确不列入的两类**（免得清单被稀释）：

- **历史快照**：`docs/08`–`docs/13` 验收报告里的"当时数字" —— 它们是**记录**，不是**声称**（改它们等于篡改验收记录）；
- **检查清单本身**：`docs/06` §9.1「上线前检查清单」这类**天生就是待办**的东西，未勾选不代表"文档撒谎"。

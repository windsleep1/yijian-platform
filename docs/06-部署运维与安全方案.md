适用日活 10 万以内。**视频建议放对象存储 + CDN，不要走应用服务器**（否则 5Mbps 带宽看 3 个人就满了）。

### 1.2 二期（拆分）

| 变更 | 触发条件 |
|---|---|
| PostgreSQL 读写分离 + 从库 | QPS > 2000 |
| Redis 主从 + Sentinel | 缓存不可用即全站不可用，需高可用 |
| API 多实例 + Nginx 负载均衡 | 单机 CPU 持续 > 70% |
| Meilisearch 独立机器 | 索引超过 100 万文档 |
| 迁 K8s | 实例数 > 3 或需要弹性扩缩容 |
| CDN 全量接管静态与视频 | 带宽成本超过 ¥2000/月 |

## 2. 环境规划

| 环境 | 用途 | 域名 | 数据 |
|---|---|---|---|
| `local` | 本地开发 | localhost | 种子数据，可随意重置 |

## 3. Docker Compose

完整文件见 `deploy/docker-compose.yml`。核心要点：

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      # 性能调优（4C8G）
      POSTGRES_INITDB_ARGS: "--encoding=UTF8 --locale=C"
    command: >
      postgres
      -c max_connections=200
      -c shared_buffers=1GB
      -c effective_cache_size=3GB
      -c work_mem=8MB
      -c maintenance_work_mem=256MB
      -c wal_level=replica
      -c archive_mode=on
      -c archive_command='test ! -f /var/lib/postgresql/wal_archive/%f && cp %p /var/lib/postgresql/wal_archive/%f'
      -c log_min_duration_statement=500
    volumes:
      - pg_data:/var/lib/postgresql/data
      - pg_wal:/var/lib/postgresql/wal_archive
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    command: >
      redis-server
      --appendonly yes
      --maxmemory 512mb
      --maxmemory-policy allkeys-lru
      --requirepass ${REDIS_PASSWORD}
    volumes:
      - redis_data:/data

  meilisearch:
    image: getmeili/meilisearch:v1.8
    environment:
      MEILI_MASTER_KEY: ${MEILI_MASTER_KEY}
      MEILI_ENV: production
      MEILI_NO_ANALYTICS: "true"
    volumes:
      - meili_data:/meili_data

  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}
    volumes:
      - minio_data:/data
```

**关键注意点**：

| 点 | 说明 |
|---|---|
| `depends_on` + `healthcheck` | 必须配 healthcheck，否则 api 会在 PG 还没起来时启动失败 |
| 数据卷命名 | 用 named volume 而非 bind mount，避免 Windows/Linux 权限问题 |
| `maxmemory-policy allkeys-lru` | Redis 存了验证码等不可丢数据时改为 `volatile-lru` 并给这些 key 不设 TTL |
| 不暴露端口到公网 | 生产环境 `ports` 只给 nginx，PG/Redis/Meili 用 `expose` 走内网 |
| 日志限制 | 每个服务加 `logging: driver: json-file, options: {max-size: 10m, max-file: 3}`，否则日志撑爆磁盘 |

## 5. Nginx 配置要点

```nginx
# 1) 限流区定义
limit_req_zone  $binary_remote_addr zone=api_limit:10m   rate=600r/m;
limit_req_zone  $binary_remote_addr zone=login_limit:10m rate=10r/m;
limit_conn_zone $binary_remote_addr zone=conn_limit:10m;

# 2) 上游
upstream api_upstream { server api:8000; keepalive 32; }
upstream web_upstream { server web:3000; keepalive 32; }

server {
    listen 443 ssl http2;
    server_name www.yijian.example.com m.yijian.example.com;

    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;

    # 安全响应头
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Content-Type-Options    "nosniff" always;
    add_header X-Frame-Options           "SAMEORIGIN" always;
    add_header Referrer-Policy           "strict-origin-when-cross-origin" always;
    add_header Content-Security-Policy   "default-src 'self'; img-src 'self' data: https:; media-src 'self' https: blob:; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; connect-src 'self' https:;" always;

    client_max_body_size 50m;
    limit_conn conn_limit 50;

    # API
    location /api/ {
        limit_req zone=api_limit burst=200 nodelay;
        proxy_pass http://api_upstream;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # 登录/验证码 严格限流
    location ~ ^/api/v1/auth/(login|sms|register|password) {
        limit_req zone=login_limit burst=5 nodelay;
        proxy_pass http://api_upstream;
        proxy_set_header X-Real-IP       $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 静态资源：长缓存 + 内容哈希文件名
    location /_next/static/ {
        proxy_pass http://web_upstream;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Service Worker 与 manifest 不能长缓存
    location ~ ^/(sw\.js|manifest\.webmanifest)$ {
        proxy_pass http://web_upstream;
        add_header Cache-Control "no-cache, must-revalidate";
    }

    # 上传文件直连 MinIO（生产建议改成 CDN 域名）
    location /media/ {
        proxy_pass http://minio:9000/yijian-media/;
        proxy_set_header Host $host;
        expires 7d;
    }

    location / {
        proxy_pass http://web_upstream;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host       $host;
    }
}

# 3) HTTP 跳转 HTTPS
server {
    listen 80;
    server_name www.yijian.example.com m.yijian.example.com;
    return 301 https://$host$request_uri;
}
```

## 6. 备份与恢复

### 6.1 备份策略

| 对象 | 方式 | 频率 | 保留 | 存放 |
|---|---|---|---|---|
| PostgreSQL 全量 | `pg_dump -Fc` | 每日 03:00 | 30 天 | 本机 + 异地对象存储 |
| PostgreSQL WAL | 归档 | 持续 | 7 天 | 本机 + 异地 |
| Redis | RDB 快照 | 每小时 | 3 天 | 本机（仅缓存，可不备份） |
| MinIO | `mc mirror` | 每日 04:00 | 版本化 | 异地 bucket |
| 配置文件 | Git | 每次变更 | 永久 | 私有仓库 |

### 6.2 备份脚本

```bash
#!/usr/bin/env bash
# deploy/scripts/backup.sh
set -euo pipefail

BACKUP_DIR="/backup/postgres"
DATE=$(date +%Y%m%d_%H%M%S)
FILE="${BACKUP_DIR}/yijian_${DATE}.dump"
KEEP_DAYS=30

mkdir -p "$BACKUP_DIR"

docker compose exec -T postgres pg_dump \
  -U "${POSTGRES_USER}" -d "${POSTGRES_DB}" \
  -Fc --no-owner --no-acl > "$FILE"

# 校验备份可读（关键：不做校验的备份等于没有备份）
docker compose exec -T postgres pg_restore --list < "$FILE" > /dev/null \
  || { echo "备份文件损坏: $FILE" >&2; exit 1; }

# 上传异地
mc cp "$FILE" "backup/yijian-db/$(basename "$FILE")"

# 清理过期
find "$BACKUP_DIR" -name "yijian_*.dump" -mtime +${KEEP_DAYS} -delete

echo "备份完成: $FILE ($(du -h "$FILE" | cut -f1))"
```

crontab：

```cron
0 3 * * *   /opt/yijian/deploy/scripts/backup.sh >> /var/log/yijian/backup.log 2>&1
0 4 * * *   /opt/yijian/deploy/scripts/mirror-minio.sh >> /var/log/yijian/backup.log 2>&1
0 5 * * 0   /opt/yijian/deploy/scripts/verify-backup.sh >> /var/log/yijian/backup.log 2>&1
```

### 6.3 恢复流程（写进 SOP，定期演练）

```bash
# 1) 停应用（保留数据库）
docker compose stop api web celery-worker celery-beat

# 2) 恢复
docker compose exec -T postgres dropdb -U yijian yijian
docker compose exec -T postgres createdb -U yijian yijian
docker compose exec -T postgres pg_restore -U yijian -d yijian --no-owner < /backup/postgres/yijian_xxx.dump

# 3) 时间点恢复（如需）—— 用 WAL 回放到指定时刻
#    见 PostgreSQL PITR 文档，recovery_target_time = '2026-09-15 14:30:00+08'

# 4) 重建索引（Meilisearch）
docker compose exec -T api python -m app.cli reindex-questions

# 5) 启动
docker compose up -d
curl -f http://localhost:8000/api/v1/health
```

**恢复演练：每季度一次，记录实际 RTO。** 没演练过的恢复方案只是纸面方案。

## 7. 监控与告警

### 7.1 监控栈

```
Prometheus  ──▶ Grafana（可视化）
    ▲
    │ 抓取
    ├── node_exporter    主机（CPU/内存/磁盘/网络）
    ├── postgres_exporter PG（连接数/慢查询/复制延迟/缓存命中率）
    ├── redis_exporter   Redis（内存/命中率/阻塞连接）
    └── /metrics（FastAPI）API（QPS/P95/错误率/各接口耗时）
Loki   ──▶ 日志聚合（结构化 JSON，带 trace_id）
Sentry ──▶ 前后端异常追踪
```

### 7.2 告警规则（告警到企业微信/钉钉）

| 级别 | 条件 | 动作 |
|---|---|---|
| **P0** | API 5xx 错误率 > 5%（5 分钟） | 电话 + 企微 |
| **P0** | 数据库连接失败 / 磁盘 > 90% | 电话 + 企微 |
| **P0** | 支付回调失败率 > 10% | 电话 + 企微 |
| **P1** | 接口 P95 > 1s（10 分钟） | 企微 |
| **P1** | Redis 内存 > 85% | 企微 |
| **P1** | 备份任务失败 | 企微 |
| **P2** | 慢查询 > 10 条/分钟 | 企微（工作日） |
| **P2** | 风控告警（刷题/短信轰炸） | 企微 |

### 7.3 业务监控（比技术监控更重要）

| 指标 | 说明 |
|---|---|
| 新增注册数 | 环比下降 > 30% 立即排查 |
| 答题提交量 | 是"心跳指标"，突降说明答题链路断了 |
| 支付成功率 | < 90% 报警 |
| 短信到达率 | < 95% 报警（换通道） |
| 交卷成功率 | < 99% 报警（考试场景绝不能丢答案） |

## 8. CI/CD

```yaml
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.12' }
      - run: pip install -e "apps/api[dev]"
      - run: pytest apps/api/tests -q --cov=app --cov-fail-under=70
      - run: ruff check apps/api
      - run: mypy apps/api/app

  build-and-deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build images
        run: |
          docker build -t $REGISTRY/yijian-api:$GITHUB_SHA apps/api
          docker build -t $REGISTRY/yijian-web:$GITHUB_SHA apps/web
      - name: Push
        run: |
          echo "$REGISTRY_PASSWORD" | docker login $REGISTRY -u $REGISTRY_USER --password-stdin
          docker push $REGISTRY/yijian-api:$GITHUB_SHA
          docker push $REGISTRY/yijian-web:$GITHUB_SHA
      - name: Migrate DB (先迁移后发布)
        run: ssh $DEPLOY_HOST "cd /opt/yijian && docker compose run --rm api alembic upgrade head"
      - name: Deploy
        run: |
          ssh $DEPLOY_HOST "cd /opt/yijian && \
            export IMAGE_TAG=$GITHUB_SHA && \
            docker compose pull && \
            docker compose up -d --remove-orphans && \
            docker image prune -f"
      - name: Smoke test
        run: |
          sleep 15
          curl -f https://www.yijian.example.com/api/v1/health || exit 1
```

**发布铁律**：

1. **先迁移数据库，再发应用**（迁移必须向后兼容：只加字段/索引，不删不改）
2. 破坏性变更分两次发布：先兼容双写 → 再切读 → 最后清理
3. 每次发布可回滚：`IMAGE_TAG` 指向旧 tag 重新 `up -d` 即可
4. 冒烟测试失败自动回滚

#### ⚠️ 关于 `npm run build`：一条**已知风险**，别以为门禁绿了就没事

**门禁不管这件事**：前端 CI job 只跑 `npm ci` / `lint` / `format:check` / `tsc --noEmit`，
**不跑 `build`**；本机也跑不通（沙箱的 `safe-delete` 守卫 + 写 `.next/trace` 报 EPERM，
**两处都发生在构建开始前，与源码无关** —— 见 `apps/admin/docs/B端联调坑.md` 坑 60）。

⇒ 于是出现一个**没人拦的窗口**：下面这一类错误，`tsc` 与 lint **全都看不见**，
**只有 `build`（或真正的部署）会暴露**：

| 只在 build/部署时暴露的错误 | 为什么静态门禁看不见 |
|---|---|
| server component 里访问 `window` / `document` / `localStorage` | `tsc` 只查类型，不查"这段代码在哪个运行时执行" |
| `next/dynamic` / 动态导入路径写错、`ssr:false` 用错位置 | 解析错误要到打包期才报 |
| `metadata` / `generateMetadata` 生成出错 | 属于构建期钩子，`tsc` 不执行它 |
| 客户端组件缺 `"use client"` | 是 Next 的约定，不是 TS 的类型 |

**动作（部署前必做）**：在**不受沙箱限制的环境**（CI 加一个 build job / 本机以外的机器）
跑一次 `npm run build`，**成功才算通过**。

> ⚠️ 不要拿"本机 build 失败"当结论 —— 那是**环境**失败，不是代码失败（坑 60 的教训：
> 报错指向处 ≠ 真正失败点）。判据是"**换个不受限的环境，它还失败吗**"。

### 9.2 考前峰值预案（考前 7 天 + 查分日）

| 动作 | 说明 |

## 10. 常见故障处置手册

| 现象 | 排查顺序 | 处置 |
|---|---|---|
| 502 Bad Gateway | ① `docker compose ps` 看 api 是否在跑 ② `docker compose logs api --tail=100` ③ 检查 DB 连接 | 重启 api；若 OOM 则加内存或减少 uvicorn worker |
| 接口大面积超时 | ① 查 PG 慢查询 `pg_stat_activity` ② 查 Redis 连接数 ③ 查 CPU/IO | 杀长事务；加缓存；临时限流 |
| 磁盘打满 | `df -h` → `du -sh /var/lib/docker/*` | 清理日志与旧镜像；扩容 |

### 1.3 表的形状 —— 它决定了三件事

```
id            BIGINT PRIMARY KEY            ← **无默认值** ⇒ 应用侧 next_id()（雪花）
user_id       BIGINT NOT NULL → users(id) ON DELETE CASCADE
target_type   VARCHAR(16) CHECK (… 'lesson','question','knowledge_point','chapter')
target_id     BIGINT NOT NULL
subject_id / chapter_id   BIGINT（可空）      ← 冗余存一份，供列表按科目筛选
content       TEXT NOT NULL
position_sec  INTEGER                       ← 视频时间戳笔记；**答题笔记恒 NULL**
is_public     BOOLEAN DEFAULT false         ← 公开笔记广场用；**本批恒 false，不读不写**
like_count    INTEGER DEFAULT 0             ← 同上
is_deleted    BOOLEAN DEFAULT false         ← ⇒ **删除 = 软删**
created_at / updated_at  +  触发器 trg_notes_updated
```

索引：`idx_notes_user(user_id, created_at DESC)`、`idx_notes_target(target_type, target_id)`、
`idx_notes_search GIN(to_tsvector('simple', content))`。

★ **没有** `(user_id, target_type, target_id)` 唯一索引 ⇒ **原设计允许"一题多条"**（见 **D1**）。
★ `updated_at` 由**触发器**维护 ⇒ 应用侧**不许**自己写它（见 §5）。

### 1.4 ★ 那个 GIN 搜索索引对中文**几乎没用**（= 本批不做搜索的理由）

`to_tsvector('simple', content)` 的 `simple` 配置**不做中文分词** —— 一长串中文会变成
**一个 token**，`plainto_tsquery` 只能整段命中。⇒ 它**看起来像个搜索能力，实际用不了**。
本批**不做搜索**（要做得先换分词方案，那是另一个议题）。
★ **不删这个索引**（删列/删索引是破坏性迁移），只是**不假装它是可用的搜索**。

## 2. 三个决策点

### D1（最重要）**一题一条** 还是 **一题多条**？→ 建议 **B（多条）**

| | A · 一题一条（就地覆盖） | **B · 一题多条（建议）** |
|---|---|---|
| 迁移 | 要加 **partial 唯一索引**<br>`(user_id,target_type,target_id) WHERE is_deleted=false` | **0**（表里本来就没有唯一索引） |
| 与表设计 | **打架**：`position_sec`（视频时间戳笔记）天然是多条 | **一致** |
| "编辑 / 删除"落到 | 那唯一一条 | **单条**（语义更明确） |
| UI 成本 | 略低 | 略高（要列表 + 单条操作） |
| 隐藏坑 | 不加 `WHERE is_deleted=false` → **软删后重建撞唯一索引**（而且只在"删了再写"时炸） | 无 |

★ 选 B ⇒ 三个写操作各自对应**一条记录**：新增 = `POST`、编辑 = `PUT /notes/{id}`、
删除 = `DELETE /notes/{id}` —— 不会出现"我编辑的到底是不是我写的那条"这种问题。

### D2 删除 = **软删**（`is_deleted = true`）—— 表就是这么设计的

- **所有读路径必须带 `is_deleted = false`**。漏一处 ⇒ "删了还在"，而且**不报错**。
- 同族：`wrong_questions.is_removed`。★ 这条要**写成用例**，不能只写在注释里（隐约定拦不住）。

### D3 答题页的笔记入口 = **就地展开面板**，**不跳页**

跳到 `/me/notes` 再回来会**丢掉当前未提交的选择**（`picked` / `revealed` 是页面内状态）
—— 答题中途跳走是**用户能感觉到的状态丢失**。
⇒ 面板在答题页内展开：**上面"新增"，下面"本题已有 N 条（可编辑 / 删）"**。
★ 面板里**不分页**（本题笔记量小）；只有列表页分页。

## 3. 接口：新增 **5 个**（路由 72 → 77，**不新开模块文件**）

| # | 方法 + 路径 | 作用 | 备注 |
|---|---|---|---|
| 1 | `GET /practice/questions/{qid}/notes` | 本题**我的**笔记（未软删） | **不分页**（面板用） |
| 2 | `POST /practice/questions/{qid}/notes` | 新增一条（body `{content}`） | 返回新笔记 |
| 3 | `PUT /practice/notes/{note_id}` | 编辑（body `{content}`） | 非本人 → 40401 |
| 4 | `DELETE /practice/notes/{note_id}` | 删除（**软删**） | 幂等：已删再删仍 200 |
| 5 | `GET /practice/notes` | 我的笔记**列表**（`subject_id` / `page` / `size`） | 分页 + 科目筛选 |

**扩展既有接口 1 处**：`GET /practice/sessions/{id}` 的每个 item 补 **`note_count`**
（与 `marked` / `favorited` 在**同一次查询**里出，**不许 N+1**）—— 面板 badge 靠它。

★ **为什么不新开 `notes.py`**：与批次 2 同理 —— 复用同一套鉴权 / 归属 / 40401 约定，
且答题页要**在同一次 session 详情**里拿到 `note_count`。
★ **为什么写接口挂在 `/practice/questions/{qid}/…` 而读列表在 `/practice/notes`**：
前三个是**题目维度**的动作（对某题写笔记），第 5 个是**跨题的我的资源**。路径名词一致化会掩盖这个差别。
★ **为什么不用 `GET /practice/notes?question_id=` 替掉第 1 个**（那样只有 4 个接口）：
两个读的**分页语义不同**（本题不限页 / 列表分页），塞进一个接口就会产生
"**传了 `question_id` 就忽略 `page`**"这类隐形规则 —— 那是**同一个参数两种含义**。
★ **为什么列表在 `/practice/notes` 而页面在 `/me/notes`**：API 按**域**（练习域），页面按 **IA**。
批次 2 的收藏已经这么做（`/practice/favorites` ↔ `/me/favorites`），保持一致。

## 5. 状态与不变量（写进代码 + 用例的那几条）

| 判据 | 为什么 |
|---|---|
| 写路径**自己 `commit()`** | 不变量 7（不 commit ⇒ 重启就没了，而且测试里看不出来） |

|---|---|---|
| 4 | **可证伪锚**：写之前断言"本题 0 条" | 否则"一开始就有 1 条"与"真的写了"长得一样 |

| 8 | **归属**：拿别人的 `note_id` 编辑/删除 → **40401 且零副作用** | 拦"用 id 猜到别人的笔记" |
| 9 | **未登录** → 40101 | — |

| 12 | **两种空态文案**：「本题还没写过笔记」vs「我的笔记是空的」 | 二者是**不同的空**（同一句文案会让人以为"我没写过"） |

**E2E 新场景 `p2c5`**（6 步，锚点用 `data-*`）：
① 进答题页 → 断言**本题 0 条**（可证伪锚）→ ② 写一条 → 出现 1 条 → ③ **刷新后还在**
（持久化，不是只改前端 state）→ ④ **编辑** → 内容变了、**仍 1 条** → ⑤ 我的 → 笔记列表**能列出**
→ ⑥ **删除** → 列表消失 + 回答题页**回到 0 条**。
★ 场景清单**三处一起改**，由**不变量 11** 当场兜住（批次 2 已验证它会红）。

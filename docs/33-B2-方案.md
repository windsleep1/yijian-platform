## 1. 侦察：三件事实

### 1.1 ★★ PWA 侧**根本不存在** user 概念（机械判据 + 对照格）

用户的担心是"不要在 PWA 里模拟用户过滤、不要传假 id"。**先量再说**：

```
判据：grep -iE "\b(user_id|userId|uid|:uid|current_user|auth|token|login|登录)\b"  apps/pwa/src/**/*.{ts,tsx,mjs}
结果：命中 10 处 —— **逐条判读，没有一处是"参数"或"过滤条件"**
```

| 命中处 | 它其实是 |
|---|---|
| `api.ts:21` | 抬头的能力对照表里写着「认证 \| **没有** —— 单机单用户（这是"零成本"的代价）」 |
| `grade.mjs:12/17/39` | 另一个意思的 token（"哪些 token 算对的答案"，指选项标号） |
| `(tabs)/layout.tsx:46` | 又一个意思的 token（设计尺寸 token，`min-h-touch`） |
| `types.ts:22/36/55` | **`Me` / `TokenPairOut` 等类型定义** —— 逐字节复制带来的、PWA 用不上的类型（见 §3.3） |
| `manifest.ts:9/22` | **过期声称**（见 §1.2） |

**对照格（硬约定 J：判据必须能被证伪）**：同一条判据跑在 `apps/web/src` 上 ⇒ **命中 62 处 / 分布 11 个文件** ⇒ 这条判据**能报红**，不是"因为正则写错所以永远 0 命中"。

⇒ **结论：`api.ts` 的函数签名不需要改。** 它们从一开始就是 `(sid)` / `(qid)` / `(nid)` / `(body)`；`request<T>(path, opts)` 内部**零身份注入**（无 uid、无 header）；`db.ts` 的四个 store 的 keyPath 是 `id` / `item_id` / `question_id` / `key`，**没有 user 维度**。
★ 用户的"不要传假 id"这条**没有被违反** —— 因为**从来没有 id 可传**。

### 1.2 ★★ 新发现（判据层面）：**"逐字节相同"不保证"在新环境里是对的"**

`apps/pwa/src/app/manifest.ts` 与 C 端**逐字节相同**（B-1 的清单里归类为 `same`），但它的注释写着：

> ⚠️ 这个路径会被 `middleware.ts` 拦到（matcher 只排除了图片与 `_next/*`），未登录访客会被
> 302 到 `/login` ⇒ 浏览器拿到的是 HTML，manifest 解析失败 ⇒ **装不上**。
> 所以 `PUBLIC_PREFIXES` 里必须有它（**不变量 10-d** 会断言这件事）。
> …★ `start_url: "/"` 在未登录时会经中间件跳 `/login` —— **这是预期**，不是 bug。

**PWA 里：没有 `middleware.ts`、没有 `PUBLIC_PREFIXES`、没有 `/login`、没有不变量 10-d。**
⇒ 这段话在 PWA 里**每一句都是假的**，而它**不报错**（正是项目红线「文档声称 ≠ 已验证」的现场）。

**它意味着什么（本批要写进 `docs/32` 的判据）**：

> 复制品门禁（不变量 12）防的是「**下游悄悄落后**」（C 端改了、PWA 没改）。
> 它**防不了**「**上游的内容在新环境里本来就不成立**」—— 后者也能让 `same` 判据**全绿**。
> ⇒ **`same` 只是"没漂移"的证据，不是"正确"的证据。** 环境相关的注释必须**逐条重审**，
> 判据 = 「**这句话在 PWA 里成立吗？**」，而不是「这个文件跟 C 端一样吗？」

**处理**：`manifest.ts` 的注释改成 PWA 口径（于是它从 `same` 变成 `fork`，要在清单里登记理由 —— 理由可判定："**它描述的那个守卫在 PWA 里不存在**"，不是"有意简化"）。同族要复查的还有几个从 C 端复制的文件（`sw-register.tsx` / `globals.css` / `(tabs)/practice/page.tsx` 的注释），本批**一起扫一遍**。

## 2. 数据层改法（4 处，全在 `api.ts`）

### 2.1 `createSession` 加 `mode`

按 `mode` 分叉，**与后端 `SessionCreateIn` 同口径**（批次 1 的 `model_validator`）：

```
mode === "wrong"  ⇒ question_ids 必填；subject_id **不许**（受了就拒）
mode === "chapter"（默认）⇒ subject_id 必填；chapter_id 可选
```

★ **不需要在 PWA 侧"校验题是不是我的"** —— 本地库里所有题都是"我的"（没有别的用户）。但**要保留"题必须存在"这一条**：`question_ids` 里有题不在本地题库里（换过包）⇒ 整批拒绝 `40401`，与后端的归属/存在性守卫**表现一致**（后端那里是"归属"，这里是"存在"，**判据形态相同：不给出指向打不开的题的会话**）。
★ 题序与"未答优先"的排序**要沿用现有那段逻辑**（C 端也是确定的、不随机）。

### 2.2 `wrongListForFuture` → `listWrong(query)` 并接进 `ROUTES`

- 改名（去掉 `ForFuture` —— 名字里的"将来"现在到了，留着就是过期声称）
- 签名改成 `(query: URLSearchParams)`，支持 `subject_id` / `marked_only` / `page` / `page_size`
- **`marked_only` 要照后端口径**：只筛"已标记"的，且**分面恒为全量**（不随筛选收缩 —— 与 `listCollections` 同一条判据）
- `ROUTES` 里加 `route("practice/wrong-questions", ...)`

### 2.3 新增 `wrongDetail(qid)`

- 返回 `WrongDetail`；**不在错题本里 ⇒ `40401`**（C 端详情页把这个 code 当**正常答案**处理，显示"这道题不在你的错题本里"）
- ★ 同一条 `40401`，**两个来源**（"没错过"与"题已不在题库里"）—— 后端是同一个 code，**保持一致**；`question_available` 用来区分展示。

### 2.4 分页

错题本列表用 `PAGE_SIZE`（与 C 端同值），分面（科目 chips）**恒为全量**。

### 3.3 新建：数据备份（`me/backup`）

用户 Q6 的硬需求（"IndexedDB 清缓存就没了"）。放在「我的」下：

- **导出**：把 `subjects` / `chapters` / `kps` / `questions` 之外的**用户数据**（`sessions` / `items` / `wrong` / `marks` / `favorites` / `notes` + `meta`）导成一个 JSON，`Blob` + `URL.createObjectURL` 触发下载。★ **不含题库**（那是可重新导入的，而且 5.85 MB 会让备份文件巨大且不可读）。
- **导入**：读文件 → 校验 `meta.bank_version` 与本机题库**一致**（不一致就拒：`question_id` 对不上，导进去会得到一堆 `question_available=false` 的孤儿行）→ **整体替换**（不是合并 —— 合并的语义"同一条笔记谁的胜"没法定义）→ 二次确认，确认框写清"这会**覆盖**当前所有答题记录"。
- ★ 与"换题库"同一个模式（清空 + 二次确认），**文案要能区分两者**。

### 3.4 顺手处理：`types.ts` 里用不上的类型

`types.ts` 是逐字节复制的，带着 `Me` / `TokenPairOut` / `ProfileOut` 等 PWA 永远不会用到的类型。**建议：保留**（删了就把"逐字节相同"这条破坏掉，而多几个未使用的类型**不产生任何运行时成本**），但**在清单里登记为"保留的未使用类型"**并写明理由 —— 理由可判定："**删它会让 types.ts 从 `same` 变 `fork`，收益只是少 30 行死代码**"。

## 4. ★★ E2E：本批最大的不确定性（必须先决策）

### 4.1 现状（实测，不是推测）

| 事实 | 影响 |
|---|---|
| `e2e-web.py` 硬编码走 `apps/web`（`args.web_base`），管道 `--e2e-web` 也是起 `apps/web` | **不能直接复用** |

### 4.2 三个候选（方案里给判据，请用户选）

| 方案 | 做法 | 好 | 坏 |
|---|---|---|---|
| **① 走真 UI（推荐）** | 给 `cdp_browser.py` 加一个 `set_file_input(selector, path)`（原生 CDP `DOM.setFileInputFiles`，约 15 行），走真实的 `/setup` 上传 | **验的是用户真会走的那条路**；顺带把"上传能力"变成项目的可复用资产 | 要碰 `cdp_browser.py`（共用的走查底座，改它要回归**全部** 8 个 C 端场景） |
| ② 注入式 | 用 `Runtime.evaluate` 在页面里 `new File([...])` 再调 `importBank()`，跳过 `/setup` 的 UI | 不动共用底座 | **跳过了被测的入口本身**（"/setup 能不能用"永远没被验过）；且注入的是内部函数名 = **测试与实现耦合** |
| ③ 预置状态 | 走查跑之前用别的脚本把 IndexedDB 填好 | 快 | 同上，且多一个"造数脚本"要维护 |

★ **推荐 ①**：它符合项目一贯的口径（"E2E 的价值在于**可证伪**"）—— 用 ②/③ 的话，"导入坏了"这件事**永远不会红**。

### 4.4 场景清单（6 个：用户要的 5 个 + 我建议加的 1 个）

| 场景 | 覆盖 | 关键断言（含**可证伪锚**） |
|---|---|---|
| **`setup`**（★ 我建议加的） | 导入 + 对账 + 首页状态 | 导入前首页显示"没有题库" → 导入后题量/选项数/各科分布**逐项等于 `meta`** → 刷新后仍在。★ 另验"换题库"的二次确认**取消时不删数据** |

| **`marks`** | 标记 | 按钮初始 0 → 点 → 变 1 → **刷新后仍在** → 错题本「只看已标记」筛得出 → 关掉回全量 |

| **`loop`**（综合） | 跨页面一致 | 答题答错 → 错题本有 → 重练答对（`retry_correct` +1）→ 收藏 + 标记 + 笔记**同时**打在这道题上 → 三个列表页**都能找到它** → 备份导出 → 清库 → 导入 → **三个列表页仍然都能找到它**（这条同时验了 §3.3 的备份） |

★ 每个场景都要先"有题库" ⇒ 共用前置 = 小包导入（`setup` 场景则把这件事本身当被测对象）。
★ **不回归 B-1**：`tools/pwa/parity.py` 仍要跑（判分对拍 12557 条）—— 它**不依赖浏览器**，所以不受本批影响，但要作为**收尾必跑项**写进验收。

`git status` 里**看不见** `me/backup/page.tsx`（它像不存在）。根因：

```
.gitignore:92    backup/        ← 无前导斜杠 ⇒ 匹配**任意层级**的 backup 目录
```

⇒ **它从写下那天起从未匹配到任何东西，第一次生效就是误伤。**

#### 文案纪律（用户提醒 ①③）：「换题库」与「数据备份」必须一眼分得清

| | 换题库（`/setup`） | 数据备份（`/me/backup`） |
|---|---|---|
| 换什么 | 整份**题库**（题目 / 章节 / 知识点） | 我的**记录**（答题 / 错题 / 收藏 / 标记 / 笔记） |
| 文件 | `pwa-bank.json`（5.85 MB） | `yijian-pwa-data-*.json`（几百 KB） |
| 副作用 | **清空全部数据** | **覆盖我的记录**（题库不动） |

落实：
· 「换题库」放在**题库信息**那一块（它属于题库），**不**和"数据"并排；
· 备份页的确认框写的是「导入会**覆盖**当前所有答题记录、错题本、标记、收藏、笔记」，
  并**逐项列出备份里有几条** —— 不是"确认导入"四个字；
· 两处**各自点明对方**（备份页底部："想换的是题库？去「我的 → 题库信息 → 换题库」"；
  导错文件时报错文案也指向 `/setup`）。
